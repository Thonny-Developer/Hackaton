# Sapa: бэкенд

REST API навигатора доступной среды. Он строит маршрут внутри здания с учётом потребностей человека: лифтов, пандусов, ширины дверей, ступеней и временных препятствий. Когда доступного пути нет, API так и отвечает и объясняет причину: «дверь 70 см, нужно 90», «лифт не работает».

* Стек: Python 3.12, FastAPI, SQLAlchemy 2 (async), PostgreSQL 17, Redis, MinIO, Caddy, Docker.
* Карта на фронте: Mapbox. Бэкенд отдаёт готовые координаты и GeoJSON, см. раздел «Карта Mapbox» в [docs/API.md](../docs/API.md).
* Документация API: Swagger на `/api/docs`. Контракт для фронтенда описан в [docs/API.md](../docs/API.md).
* Пример графа здания для импорта: [docs/demo_building.json](../docs/demo_building.json).

## Запуск

Весь проект (фронтенд, API, PostgreSQL, Redis, MinIO, Caddy) поднимается одной командой из **корня репозитория**: `docker compose up -d --build`. Подробности, деплой на VPS и переменные описаны в [корневом README](../README.md).

Команды бэкенда в Docker запускаются из корня репозитория:

```bash
docker compose exec api python -m app.cli create-admin --email admin@example.com
docker compose exec api python -m app.cli seed      # пересоздать демо-здание с нуля
docker compose logs -f api
```

При старте контейнер `api` сам применяет миграции и, если `SEED_DEMO=true`, создаёт демо-здание. Если оно уже есть, повторный старт его не трогает, поэтому правки и препятствия не пропадают.

## Как это устроено

```
Caddy :80/:443 ──► /api/* ──► api (FastAPI, uvicorn, 2 воркера)
   │
   └─ /  ──► собранный фронтенд (статика)
                     │
        внутренняя сеть без выхода наружу
                     │
         ├── PostgreSQL   граф зданий, пользователи, препятствия
         ├── Redis        счётчики rate limit
         └── MinIO        картинки схем этажей
```

### Модель данных

`Building` → `Floor` → `Node`, плюс `Edge` между узлами и `Obstacle` на узле или ребре.

* У узла есть координаты `x`/`y` в пикселях схемы этажа. Масштаб задаётся в `floor.meters_per_px`.
* Этаж можно привязать к карте: `geo_origin_lat`/`geo_origin_lon` задают точку, где лежит левый верхний угол схемы, а `geo_rotation_deg` поворот по часовой стрелке от севера. После этого API отдаёт для узлов `geo` в формате `[lon, lat]`, углы схемы `plan_corners` для Mapbox image source и GeoJSON этажа и маршрута ([app/services/geo.py](app/services/geo.py), [app/services/geojson.py](app/services/geojson.py)). Координаты входов для маршрута с улицы тоже берутся из привязки, ручные `lat`/`lon` у узла имеют приоритет.
* У ребра есть тип (`corridor`, `door`, `stairs`, `elevator`, `ramp`, `lift`, `outdoor`) и параметры доступности: `width_cm`, `steps`, `slope_pct`, `threshold_cm`. Если `length_m` не указана, длина считается по координатам, а между этажами по `floor.height_m`.
* Препятствие действует с `starts_at` до `ends_at`, его можно выключить флагом `is_active`. Если указан `reduced_width_cm`, проход не перекрывается, а сужается.

### Поиск маршрута

Вся логика лежит в [app/services/graph.py](app/services/graph.py) и не зависит от БД, поэтому покрыта юнит-тестами.

1. Из рёбер отбрасываются те, что не подходят профилю (лестница, узкий проход, крутой уклон, высокий порог) или перекрыты действующим препятствием.
2. Dijkstra ищет путь по оценке времени в секундах: ходьба со скоростью профиля, ожидание лифта, время на лестницу.
3. Если пути нет, поиск повторяется без части ограничений. Так становится понятно, что именно мешает: профиль, препятствия или граф вообще не связан. Каждое мешающее место попадает в ответ отдельной строкой.
4. Найденный путь превращается в шаги с поворотами налево и направо и переходами между этажами. Тексты есть на RU, KK и EN ([app/services/i18n.py](app/services/i18n.py)).

Препятствие на любом узле лифта выключает всю шахту. Сломанный лифт не работает ни на одном этаже.

### Кэш графа

Граф каждого здания держится в памяти воркера. Любое изменение узлов, рёбер, этажей или препятствий увеличивает `buildings.graph_version` в той же транзакции. Перед построением маршрута воркер читает только эту версию (один запрос по первичному ключу) и перечитывает граф, если версия изменилась. Поэтому кэш остаётся корректным при нескольких воркерах.

### Безопасность

* **БД и хранилище недоступны снаружи.** PostgreSQL, Redis и MinIO подключены только к внутренней сети Docker (`internal: true`), их порты не публикуются. Схемы этажей отдаёт сам API.
* **Запись только с токеном.** Изменять данные могут роли `editor` и `admin` с JWT (HS256, по умолчанию живёт 12 часов). Пароли хранятся в argon2. Пользователь перечитывается из БД на каждый запрос, поэтому отключённый аккаунт перестаёт работать сразу. Удалять здания и управлять пользователями может только `admin`.
* **Rate limit по IP** через Redis: общий лимит, отдельные лимиты на маршрут, поиск и маршрут с улицы, жёсткий лимит на вход (5 в минуту). Реальный IP выставляет Caddy, а подделанный клиентом `X-Forwarded-For` он отбрасывает.
* **Защита от тяжёлых запросов.** Caddy ограничивает тело запроса 12 МБ и задаёт таймауты. uvicorn ограничивает число одновременных соединений. Все списки отдаются постранично (не больше 200 записей), у строк и чисел есть границы, импорт графа ограничен по размеру. Поиск маршрута выполняется в пуле потоков и не блокирует остальные запросы.
* **Загрузка схем.** Тип файла определяется по содержимому, а не по расширению. Изображения проверяются через Pillow, включая защиту от «бомб декомпрессии». SVG разбирается через defusedxml, из него удаляются скрипты, обработчики `on*`, `foreignObject` и внешние ссылки. Файлы отдаются с `Content-Security-Policy` и `nosniff`.
* **Ключи внешних API** хранятся только на сервере. Фронт работает с 2GIS и ORS через бэкенд, а поиск зданий в 2GIS доступен только редакторам, чтобы посторонние не тратили квоту.
* В режиме `ENV=prod` API не стартует со слабым `JWT_SECRET` (короче 32 символов или со значением по умолчанию).

## Внешние API

Они нужны только для этапа «маршрут с улицы» (`POST /api/v1/route/full`) и для импорта зданий из 2GIS. Без ключей всё остальное работает как обычно.

| Переменная | Где взять | Что включает |
|---|---|---|
| `DGIS_API_KEY` | [platform.2gis.ru](https://platform.2gis.ru) | Поиск и импорт зданий, пеший маршрут по улице |
| `ORS_API_KEY` | [openrouteservice.org](https://openrouteservice.org/dev/#/signup), бесплатно | Уличный маршрут для колясок с учётом уклонов, бордюров и ширины |

Порядок выбора для уличного участка такой. Для профилей с ограничениями сначала пробуется ORS, потом 2GIS. Если не ответил ни один, расстояние оценивается по прямой. В ответе всегда указано, проверялась ли доступность улицы (`accessibility_checked`). Ответы внешних API кэшируются в памяти на 10 минут.

## Почта

Письма отправляются через SMTP, по умолчанию через Gmail ([app/services/mailer.py](app/services/mailer.py)):

* ссылка для сброса пароля (`POST /api/v1/auth/forgot-password`);
* уведомление админам, когда отмечено новое препятствие.

Письма уходят в фоне, поэтому недоступный почтовый сервер не тормозит API: ошибка только пишется в лог. Без `SMTP_HOST` почта выключена, а в режиме разработки текст письма со ссылкой выводится в лог.

Как подключить Gmail:

1. Включите двухэтапную аутентификацию в Google-аккаунте, с которого будут уходить письма.
2. Создайте пароль приложения: https://myaccount.google.com/apppasswords. Google покажет 16 символов.
3. В `.env` укажите `SMTP_HOST=smtp.gmail.com`, `SMTP_USER=<адрес Gmail>`, `SMTP_PASSWORD=<пароль приложения без пробелов>` и `PUBLIC_URL=<адрес сайта>`.
4. Перезапустите API и проверьте почту:

```bash
docker compose up -d api
docker compose exec api python -m app.cli test-email --to you@gmail.com
```

Обычный пароль от аккаунта Gmail не подойдёт, будет ошибка `535 Username and Password not accepted`. Бесплатный Gmail отправляет до 500 писем в сутки, для уведомлений этого хватает.

## Разработка без Docker

Нужны [uv](https://docs.astral.sh/uv/) и PostgreSQL (можно поднять только БД: `docker compose up -d db`, но тогда пробросьте её порт в отдельном `docker-compose.override.yml`).

```bash
uv sync
export DATABASE_URL=postgresql+asyncpg://sapa:sapa@localhost:5432/sapa
uv run alembic upgrade head
uv run python -m app.cli seed
uv run python -m app.cli create-admin --email admin@example.com
uv run uvicorn app.main:app --reload
```

Без `REDIS_URL` лимиты хранятся в памяти процесса, для разработки этого достаточно. Без MinIO работает всё, кроме загрузки схем.

### Тесты

```bash
uv run pytest                      # на SQLite, ничего поднимать не нужно
TEST_DATABASE_URL=postgresql+asyncpg://sapa:sapa@localhost:5432/sapa_test uv run pytest
```

Второй вариант гоняет те же тесты на настоящем PostgreSQL. **База из `TEST_DATABASE_URL` очищается**, так что не указывайте рабочую.

### Миграции

После изменения [app/models.py](app/models.py):

```bash
uv run alembic revision --autogenerate -m "что поменялось"
uv run alembic upgrade head
```

Перед коммитом проверьте сгенерированный файл в `alembic/versions/`.

## Команды

| Команда | Что делает |
|---|---|
| `python -m app.cli create-admin --email E [--password P] [--role admin\|editor]` | Создать пользователя или сменить ему пароль и роль. Без `--password` спросит его интерактивно |
| `python -m app.cli seed` | Создать или пересоздать демо-здание |
| `python -m app.cli seed --if-missing` | Создать демо-здание, только если его ещё нет |
| `python -m app.cli export-demo --out file.json` | Сохранить демо-здание в формате импорта |
| `python -m app.cli test-email --to E` | Отправить тестовое письмо и проверить настройки SMTP |

В Docker команды запускаются через `docker compose exec api ...`.

| Переменная | По умолчанию | Назначение |
|---|---|---|

| `CORS_ORIGINS` | localhost:3000, localhost:5173 | Адреса фронта на другом домене через запятую. В Docker фронт и API на одном домене, нужно только для `npm run dev` |

| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | | Доступ к PostgreSQL |
| `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD` / `MINIO_BUCKET` | | Доступ к MinIO и имя бакета |
| `RATE_LIMIT_DEFAULT` | `120/minute` | Общий лимит на IP |
| `RATE_LIMIT_ROUTE` | `30/minute` | `POST /route` |
| `RATE_LIMIT_SEARCH` | `60/minute` | `GET /search` |
| `RATE_LIMIT_OUTDOOR` | `10/minute` | `POST /route/full` |
| `RATE_LIMIT_LOGIN` | `5/minute` | Вход |
| `DGIS_API_KEY`, `ORS_API_KEY` | пусто | Внешние API, необязательно |

## Ограничения

* Внутренний маршрут строится в пределах одного здания. Переходы между корпусами можно описать ребром `outdoor` только внутри одного здания в базе.
* `POST /route/full` ведёт только с улицы внутрь здания. Обратного направления пока нет.
* OpenRouteService не поддерживает казахский язык, поэтому для `lang=kk` уличные подсказки приходят на русском.
* Официальные образы `minio/minio` больше не публикуются. В compose используется `bitnamilegacy/minio:2025.4.22`, это замороженная сборка того же сервера без обновлений. Бэкенд работает с хранилищем по S3 API, так что для продакшена образ можно заменить на любое S3-совместимое хранилище, не меняя код.
